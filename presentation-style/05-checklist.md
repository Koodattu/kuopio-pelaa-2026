# 05 · Checklist

Run before the first rehearsal and again before the event.

## Structure

- [ ] Slide count fits the budget in [04](04-deck-template.md#slide-budget)
      (~60–75 points for 60 minutes).
- [ ] The title question is answered explicitly.
- [ ] The agenda notes match the order of the talk, or the order is
      deliberately different and the section returns show where we are.
- [ ] **One summary only.** The takeaways corkboard and the closing slide say
      the same three things.
- [ ] Each case study is 2–4 slides. No more than two full cases per section.
- [ ] Each concept has **one** framework. No two different three-box
      definitions of the same thing back to back.
- [ ] Sub-areas get roughly equal time, weighted by audience interest (not by
      the speaker's own speciality).
- [ ] Foundation material (definitions, "chatbot vs. agent", "free vs. paid")
      sits **before** the demos it explains, not after.
- [ ] No tangents whose link to the topic is only in the speaker's head. If
      the slide doesn't say why it belongs, cut it.
- [ ] The personal showcase has a "what the tool did vs. what I decided"
      slide; otherwise it is a product demo.

## Slides

- [ ] Every content slide has a title, a subtitle and a bottom line.
- [ ] Every claim slide has a `Lähde:` line, and the source actually supports
      that slide (no copy-paste from the previous slide).
- [ ] Numbers that come from different studies are not drawn as one trend.
- [ ] Chart headlines match what the chart shows (e.g. a steady curve since
      2009 does not prove a recent cause).
- [ ] Illustrative charts are labelled as illustrative.
- [ ] Faces in quote grids have names on the slide, not just in the source.
- [ ] Dark screenshots are readable from the back row; otherwise crop to one
      area or demo live.
- [ ] No duplicated statistics across sections; refer back verbally instead.
- [ ] One meme per joke.
- [ ] AI-generated illustrations, if any, are disclosed on a slide.

## Housekeeping

- [ ] No stray test slides ("ON", "End of slideshow", blank slides).
- [ ] Backup and parked slides are **hidden** or in a separate file, not after a
      "last slide" marker.
- [ ] Fonts embedded (File → Options → Save → Embed fonts) or Bungee installed
      on the presenting machine.
- [ ] Videos play from the file on the presenting machine, offline.
- [ ] QR codes tested from the back of the room.
- [ ] Workshop URL and access code work on the venue network.
- [ ] Spell-check pass. Recurring Finnish slips to look for: compound words
      written apart (`tekoäly pelimoottori` → `tekoälypelimoottori`,
      `ohjelmistokehitys ala` → `ohjelmistokehitysala`), `ennenkuin` →
      `ennen kuin`, `riippuu sitä` → `riippuu siitä`, `sekä… kuin myös` →
      `sekä… että`, hyphen in `100-sivuinen`, capitalised surnames
      (`Ala-Rantala`).

## Rehearsal

- [ ] Timed run-through including pauses for audience answers.
- [ ] Each video's length known; trim to the moment that matters.
- [ ] A plan B for the poll if the voting tool fails (show of hands).
- [ ] A list of slides to skip if running late, marked in the notes.
